# Examples

Three runs of the agent, exported with `scripts/export_example.py`. Each folder has the report (`report.md`, which GitHub shows with its charts), the same report as one self-contained page (`report.html`: download it and open it in a browser), and, for every task, the script it ran (`analysis.py`) and its findings, recorded facts and reviews (`result.json`). Every number in a report was checked against the facts its scripts recorded.

| Example | Data | What to look at | Run |
|---|---|---|---|
| [life-expectancy](life-expectancy/report.md) | WHO life expectancy, 2,938 country-years × 22 columns; target: life expectancy | The longest run: 11 tasks, 5 of them follow-ups the lead added, with tests that allow for repeated countries. Then [three questions asked after the report](life-expectancy/questions.md): one answered from recorded facts, one that needed a new model test on unseen countries, one the data can't answer | Claude Haiku 5.5, `hosted` preset, 16.2 min, $0.20 (the questions: $0.03) |
| [titanic](titanic/report.md) | 891 Titanic passengers; target: survived | The familiar dataset, for comparing with analyses you know. The eval judge found every expected finding and no false claim | Claude Haiku 5.5, 8.2 min, $0.10 |
| [leakage-trap](leakage-trap/report.md) | 1,000 synthetic subscriptions; target: churned | A trap: `refund_issued` copies the target in 97.5% of rows. The report flags it as leakage, analyses churn without it, and says the near-perfect models with it reflect the leak, not a driver of churn | Claude Haiku 5.5, 8.1 min, $0.08 |

**What isn't included:** the data, every LLM call and the state after each step (they are in the run directory the agent writes, `runs/<run>/`), and the objects tasks passed to each other.

**Where the data comes from**
- Life expectancy: the WHO-based "Life Expectancy (WHO)" dataset on [Kaggle](https://www.kaggle.com/datasets/kumarajarshi/life-expectancy-who) (`Life Expectancy Data.csv`); see its page for the licence. The agent had never been run or tuned on it.
- Titanic: the 891 passengers of Kaggle's `train.csv`, as in the [quickstart](../README.md#quickstart).
- Leakage trap: generated by the eval harness (`evals/generators.py`, case `leakage`, seed 6), with known answers in [evals/cases/leakage.yaml](../evals/cases/leakage.yaml).

**Versions:** life expectancy ran on the Phase 5 code (2026-11-18), Titanic on `v0.3.1`, the leakage trap on `v0.3.0-phase3`. The Titanic and leakage runs come from the eval suites ([phase3.md](../docs/eval/phase3.md)); their pages show no cost, which the eval results record instead.
